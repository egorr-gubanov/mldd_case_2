# Пилот и критерии успеха

## Цель пилота

Проверить, что система может стабильно помогать операторам КПП в реальных условиях предприятия и при этом не создает недопустимых рисков безопасности.

Пилот не должен сразу полностью заменять текущий процесс. На первом этапе система работает как помощник: выдает решение и уверенность, а оператор подтверждает спорные случаи.

## Масштаб пилота

| Параметр | Значение |
| --- | --- |
| Проходные | 1-2 КПП |
| Сотрудники | 300-500 человек |
| Длительность | 4-6 недель |
| Основной сценарий | пропуск + проверка лица |
| Режим работы | автоматическое решение с ручным контролем исключений |

## Этапы пилота

1. **Подготовка данных.** Проверяем справочник сотрудников, пропуска, эталонные фотографии и согласия на обработку данных.
2. **Настройка оборудования.** Устанавливаем камеры, проверяем освещение и углы съемки.
3. **Технический запуск.** Интегрируем терминал КПП, ML-сервис, журнал событий и операторский интерфейс.
4. **Теневой режим.** Система принимает решения, но не управляет турникетом. Оператор видит подсказки.
5. **Ограниченный рабочий режим.** Система открывает турникет при высокой уверенности, спорные случаи уходят оператору.
6. **Анализ результатов.** Считаем метрики, разбираем ошибки, выбираем пороги.
7. **Решение о масштабировании.** Формируем список доработок для production.

## Критерии успешного пилота

| Критерий | Целевое значение |
| --- | --- |
| p95 времени проверки | не более 2 секунд |
| Доля автоматических штатных проходов | не менее 90% |
| Ложные допуски | 0 в пилоте или ниже согласованного порога |
| Ложные отказы | не создают критичных очередей |
| Полнота журнала | 100% решений записаны |
| Доступность пилотного контура | не ниже 98.5% |
| Удовлетворенность операторов | операторы понимают причины решений и не обходят систему |

## Что измеряем каждый день

- количество проходов;
- количество автоматических допусков;
- количество ручных проверок;
- причины ручных проверок;
- среднюю, p95 и p99 задержку;
- ошибки камеры и сети;
- спорные случаи и жалобы сотрудников;
- расхождения между решением системы и решением оператора.

## Решение после пилота

Возможны три результата:

- **масштабировать** — если критерии успеха выполнены и есть только небольшие доработки;
- **продлить пилот** — если качество близко к целевому, но есть понятные причины ошибок;
- **остановить внедрение** — если риски безопасности или эксплуатации слишком высоки.

## Подготовка к защите

На защите важно подчеркнуть, что пилот спроектирован безопасно: система сначала проверяется в теневом режиме, затем работает только на ограниченном контуре, а ручная проверка остается доступной всегда.
