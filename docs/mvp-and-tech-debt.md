# MVP и технический долг

## Принцип MVP

MVP должен доказать, что система реально помогает проходной, но не должен пытаться сразу закрыть все возможные сценарии. Поэтому в первой итерации выбираем самый понятный и безопасный сценарий: сотрудник предъявляет пропуск, а система проверяет, что лицо перед камерой соответствует владельцу пропуска.

## Что входит в MVP

| Блок | Что делаем |
| --- | --- |
| КПП | 1-2 проходные |
| Пользователи | 300-500 сотрудников |
| Сценарий | пропуск + лицо |
| Камера | получение кадра и контроль качества |
| ML | face verification |
| Решение | допуск, отказ, ручная проверка |
| Оператор | простой экран спорных случаев |
| Журнал | запись каждого решения |
| Мониторинг | latency, ошибки, доля ручных проверок |

## Почему не делаем сразу identification

Идентификация без пропуска выглядит эффектно, но для MVP она рискованнее:

- нужно сравнивать человека со всей базой;
- выше шанс похожих кандидатов;
- сложнее объяснить решение оператору;
- выше требования к качеству эталонных данных;
- сложнее доказать безопасность на защите проекта.

Поэтому identification оставляем как развитие после успешного пилота.

## Что остается техническим долгом

| Долг | Почему можно отложить |
| --- | --- |
| Идентификация без пропуска | не нужна для проверки базовой ценности |
| Автоматическое переобучение | сначала достаточно версионирования модели |
| Продвинутая аналитика | в MVP хватит базовых отчетов |
| Интеграция со всеми HR-процессами | можно начать с выгрузки справочника |
| Массовая пересъемка всех сотрудников | в MVP достаточно пилотной группы |
| Мобильные интерфейсы | оператор работает на КПП |

## Критерии готовности MVP

- система установлена на пилотных КПП;
- данные пилотной группы загружены;
- камера стабильно получает пригодные кадры;
- ML-сервис возвращает решение и уверенность;
- оператор видит спорные случаи;
- все события пишутся в журнал;
- есть отчет по метрикам пилота.

## План развития после MVP

1. Масштабирование на все 10 проходных.
2. Улучшение качества эталонных фото.
3. Настройка порогов по каждой КПП.
4. Расширенная аналитика безопасности.
5. Тестирование identification-сценария.
6. Интеграция с кадровыми процессами увольнения и изменения прав доступа.
