# Требования к системе

## Бизнес-требования

| ID | Требование | Обоснование |
| --- | --- | --- |
| BR-1 | Проверять личность сотрудника при проходе через КПП | основная цель продукта |
| BR-2 | Поддерживать 10 проходных предприятия | соответствует масштабу кейса |
| BR-3 | Работать с базой примерно на 5000 сотрудников | соответствует масштабу предприятия |
| BR-4 | Снижать риск прохода по чужому пропуску | ключевой эффект для безопасности |
| BR-5 | Сохранять возможность ручной проверки | нужно для спорных случаев и отказоустойчивости |
| BR-6 | Вести журнал всех решений | нужно для расследований и аудита |
| BR-7 | Соблюдать требования к персональным и биометрическим данным | работа с лицом относится к чувствительным данным |

## Функциональные требования

| ID | Требование | Приоритет |
| --- | --- | --- |
| FR-1 | Считывание пропуска сотрудника на КПП | must |
| FR-2 | Получение изображения лица с камеры | must |
| FR-3 | Проверка качества изображения | must |
| FR-4 | Сравнение лица с эталонным шаблоном владельца пропуска | must |
| FR-5 | Принятие решения: допуск, отказ, ручная проверка | must |
| FR-6 | Отображение результата оператору | must |
| FR-7 | Запись события доступа в журнал | must |
| FR-8 | Администрирование сотрудников и шаблонов | should |
| FR-9 | Отчеты по качеству работы системы | should |
| FR-10 | Идентификация без пропуска | could |

## Нефункциональные требования

| Категория | Требование |
| --- | --- |
| Производительность | p95 времени проверки не выше 2 секунд в production |
| Доступность | 99.5% для центральных сервисов после промышленного внедрения |
| Безопасность | шифрование данных, RBAC, аудит административных действий |
| Масштабируемость | возможность роста до 10000 сотрудников и 20 проходных |
| Отказоустойчивость | при сбое ML или сети проходная переходит в ручной режим |
| Поддерживаемость | модели, пороги и шаблоны должны версионироваться |
| Наблюдаемость | метрики latency, error rate, FAR/FRR, доля ручных проверок |

## Роли пользователей

| Роль | Что делает |
| --- | --- |
| Сотрудник | проходит через КПП |
| Оператор КПП | контролирует спорные случаи и ручной режим |
| Администратор безопасности | управляет правами доступа и инцидентами |
| HR-специалист | актуализирует данные сотрудников |
| ML-инженер | анализирует качество модели и обновляет конфигурации |
| Системный администратор | поддерживает инфраструктуру и мониторинг |

## Границы системы

Входит в проект:

- проверка лица при проходе;
- интеграция с пропусками и турникетом;
- хранение событий доступа;
- операторский интерфейс;
- мониторинг и аудит.

Не входит в MVP:

- распознавание эмоций;
- контроль дисциплины сотрудников;
- автоматическое наказание за нарушения;
- распознавание всех людей на территории предприятия;
- прогнозирование посещаемости.
